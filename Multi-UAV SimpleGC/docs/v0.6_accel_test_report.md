## 实现

- `parallel_batch.prepare()` 原函数完全未改；原生产 CLI 也未改。独立 `scripts/prepare_parallel_subset.py` 调用 `parallel_subset.prepare_subset()`，只接受不重复、存在且覆盖完整 family 的 mission_id 列表。
- 复制完整来源 bundle，不重新生成、不重写其清单/manifest/task/scene；所有文件（含非 JSON）逐文件 SHA-256 比较。源目录在复制前后复验；新批次运行时复验复制品的文件集合及哈希。
- 新计划按原清单顺序选择任务，局部 global_index 连续化，另存原索引；原 mission_id、family_id、seed、split、entry 不变，family 整体分配到 shard。
- 仅 subset 计划在完整性检查中使用子集。finalize 的审计清单派生到 bundle 外，只含选中 family，避免将剩余 286 个 family 报为缺失；不虚构子集的生成接受率。
- 计划、批次目的文件及后续导出 manifest 标记 `purpose=pilot`、`training_data=false`；原 split 保留只为配对，不能将此批次当训练集。
