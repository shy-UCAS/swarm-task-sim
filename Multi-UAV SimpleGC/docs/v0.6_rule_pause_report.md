## 实现及等价性核实

1. 旧判定在 `register_completion()` 登记每次完成后执行，不在派发前单独判定。Ctrl+C 设置暂停请求，在安全边界停止派发、排空在飞 worker。
2. 新规则复用暂停路径；阈值、异常定义不变。`paused=true`、`stopped_reason=null`，事件区分 manual/rule，保存原因与触发窗口全部异常 run_id/reasons、UTC、触发 attempt、排空后的完成尝试与时间。
3. `run --resume` 仍显式执行，预算、结果和完成顺序前缀不变；`resume_events` 保存续跑记录，`rule_pause_count` 累计且不限次数。排空期间确认违规优先变为规则停止；恢复未登记证据时新发现的规则暂停不能被同一次 resume 自动消耗。
4. 连续滚动窗口不清空，仅“本次异常且登记后窗口达阈值”触发。正常的新运行不会因旧异常再次暂停；最后一个任务触发规则暂停也需复核，续跑后才转 completed。
5. 首次触发前严格等价：正常运行加入窗口时，异常数只能不变或减少；第一次从阈值下方达到 5 必须由异常运行触发。因此额外条件不改变首次触发时刻。离线枚举 1,024/1,024 个十次尾序列（前接 20 次含 4 个异常的窗口，覆盖窗口淘汰）一致。
6. `progress.json` 和 CLI `status` 增加暂停类别、原因摘要和累计次数。旧滚动停止不迁移，既有 stop_events 及硬违规证据仍阻止清除停止原因后续跑。
7. 命令文档补齐人工检查、独占机器与资源采样；每次采集整机 CPU/内存、内存和 CPU 各前五进程，含名称/PID/占用量，写到批次外。CPU 使用当前格式化占用率，不用累计 CPU 时间。
