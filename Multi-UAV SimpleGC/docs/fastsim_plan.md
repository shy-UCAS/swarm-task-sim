# 简易无人机集群仿真器（fastsim）实现计划

> **给执行方（新的 Claude Code 会话）：** 本文件自包含。第一部分是背景与规则，第二部分是设计，第三部分是分阶段任务。每个阶段结束都要停下汇报，等用户复核后再继续。
> **一句话目标：** 用纯 Python 写一个轻量的多无人机运动学仿真器，复用现有的规划、判定、描述和导出流水线，每小时生成数千条以上的轨迹数据；并用已有的 SITL 数据做校准和配对验证，证明它"足够像"真实飞控。

# 第一部分：背景与规则

## 1. 项目背景

- **课题：** Traj2Language，无人机集群轨迹的语义理解与自然语言对齐。数据线仓库为 `swarm-task-sim`（本机 `F:/CASIA/Drone Swarm Situational Awareness Algorithm/Simulation-dev`，GitHub `shy-UCAS/swarm-task-sim`）。
- **现状：** 数据由 ArduCopter SITL（真实飞控固件）生成。4 路并行时每小时约 50 条，还有约 3% 的进程崩溃、时钟对齐、端口和进程管理等问题。v0.6 的 SITL 正式生产（900 条，三种意图）正在收尾。
- **定位（重要）：** fastsim **不替换** SITL，而是分工：
  - **fastsim：** 大规模、可复现、可随意加噪声和扰动，用于训练数据，以及自监督预训练所需的大量无标注轨迹；
  - **SITL：** 较小规模的高保真数据，用于校准 fastsim 和最终评测。
  - 论文里的设计是"在 fastsim 上训练，在 SITL 上测试"，两层数据之间的差距可作为"仿真到真实"差距的代理。

## 2. 必读

1. 仓库根目录的 `README.md`、`CLAUDE.md`；
2. `Multi-UAV SimpleGC/docs/v06_formal_plan.md`（三种意图、飞法、family 规则）；
3. `Multi-UAV SimpleGC/docs/v0.6.1_time_audit.md`（时间语义，以及各类判定需要哪些产物）；
4. `Multi-UAV SimpleGC/docs/v0.6.1_time_validation_report.md`（配对比较方法，以及 r1/r2 自然波动的数值）；
5. `Multi-UAV SimpleGC/docs/data_contract_v0.md`（数据契约，含两项 P2 已知特性）。

## 3. 硬性规则

1. **在独立的 git worktree 中开发**：例如 `../Simulation-fastsim`，分支 `fastsim`，基于当前 `main`。**不得修改 `Simulation-dev` 工作目录**：SITL 正式生产（r3）可能正在运行，仓库文件一改，受保护文件哈希就会变化，批次会被拦停。r3 收尾后再合并回 `main`。
2. 不碰冻结归档 `Simulation`、任何已有批次目录、`Simulation-dev-wip`。SITL 数据**只读**使用，所有输出写到 `SwarmData/fastsim/` 下。
3. **SITL 路径的行为一行不改**：v0.5、v0.6、v0.6.1 的生成、执行、分析、导出全部保持原样。DR130 金标准回归、v0.5 示例加载、现有 CI 清单必须继续通过。
4. **r3 运行期间**，本机上的计算类工作（校准、批量生成）设为低优先级，单进程运行，以免干扰 SITL 的时钟对齐。大批量生成放到 r3 结束之后。
5. 不放宽任何判定阈值；判定器、事实提取、描述模板**原样复用**，不为 fastsim 另写一套。
6. 推送以远端 CI 为准；推送被拦截时，告诉用户手动推送。
7. 汇报只写结论、异常和证据位置，数字附分母，用中文。

# 第二部分：设计

## 5. 总体结构

```
场景采样 + family 规则 + 规划器（全部复用）
        │  规划结果：各机航点序列、阶段角色、悬停、出发延迟
        ▼
fastsim 内核（新写）：质点动力学 + 航点跟踪控制 + 扰动与噪声
        │  真值轨迹（精确仿真时间） + 观测轨迹（真值加观测噪声） + 阶段事件
        ▼
适配层（新写）：输出与 v0.6.1 相同格式的运行产物，时间轴为精确仿真时间
        ▼
分析、判定、事实提取、描述生成、数据集导出、加载器（全部复用）
```

**原则：** SITL 只负责"执行"这一环，fastsim 只替换这一环。上下游代码尽量不动，确保两层数据的标签和描述来自**同一套代码**。

## 6. 仿真内核

### 6.1 状态与积分

- 每架飞机的状态为 3D 位置 `p`、速度 `v`（ENU，米、米/秒），内部步长 `dt = 0.01 s`（可配置），输出 10 Hz（每仿真秒 10 帧）。
- **从空中开始：** 每架飞机在起飞位置正上方、任务高度处以悬停状态开始。分析窗口本来就从"起飞稳定"之后开始，起飞和降落不需要模拟。
- 多机互不影响（不模拟碰撞和气流干扰），各机独立积分。
- 用 NumPy 实现。先写清晰的逐机版本，需要提速时再做多机向量化（或用 numba），不做 C++。

### 6.2 航点跟踪控制（模仿 ArduCopter 的航线飞行）

目标是复现 SITL 轨迹的主要特征：巡航速度、加减速、转弯时减速、到点悬停、阶段间释放。建议的最小模型：

1. **期望速度：** 指向当前目标航点，大小取巡航速度（来自任务的共用速度参数），接近航点时按"能在到达时减速到所需速度"的规则降速，即 `v ≤ sqrt(2·a_max·d)`；
2. **转弯处理：** 中间航点处，若进入和离开方向的夹角超过阈值，则按转弯减速规则限制过点速度；夹角很小时直接通过。接受半径、转弯减速规则作为可校准参数；
3. **速度响应：** 实际速度以一阶滞后（时间常数 `τ`）跟随期望速度，同时满足最大加速度 `a_max` 和最大加加速度 `j_max` 限制；水平和垂直分开限幅；
4. **悬停与释放：** 到点确认驻留、终点悬停（2 s）、阶段释放偏移、机间错峰出发，全部按规划结果中的仿真秒执行，语义与 v0.6.1 审查表一致；
5. **可校准参数：** `a_max`、`j_max`、`τ`、接受半径、转弯减速规则的参数、垂直速度和加速度上限。缺省值参考 ArduCopter 4.0 的 WPNAV 默认参数（例如 `WPNAV_ACCEL`），再用第 8 节的校准确定。

如果最小模型校准后达不到第 8.3 节的标准，再考虑增加复杂度（例如转弯采用样条曲线）。**不要一开始就做复杂模型。**

### 6.3 扰动与噪声（第 3 阶段才启用；校准时全部关闭）

| 类别 | 模型 | 作用 |
|---|---|---|
| 风 | 恒定风加 Ornstein–Uhlenbeck 阵风，以加速度扰动形式作用 | 轨迹层面的多样性和真实感 |
| 跟踪误差 | 小幅过程噪声 | 避免轨迹"完美得不真实" |
| 观测噪声 | 位置、速度加高斯噪声，可选慢变偏差 | 观测通道与真值通道分离（双通道判定才有意义） |
| 观测丢点 | 伯努利或马尔可夫成段丢失 | 模拟遥测或雷达跟踪中断 |

**防捷径规则（P0）：**
- 风和噪声参数属于**场景条件**，在 family 内三种意图之间**共用**，与意图无关；
- 所有噪声参数和随机种子写入元数据；种子从任务种子派生，保证逐位可复现。

### 6.4 适配层与输出

- 优先方案：输出与 v0.6.1 SITL 运行**相同结构的运行产物**（采样、事件、元数据、阶段窗口等），时间轴直接是精确仿真时间（时钟模型为恒等映射，标记为 `time_base="sim_exact"`），然后走**现有的** analyze → export → audit → describe → load 流程。执行方先在第 0 阶段查清现有分析流程需要哪些产物，提出最小的适配方案。
- SITL 特有的检查（参数回读、固件门禁、端口、机载任务参数、时钟拟合）在 fastsim 中不适用。用显式的数据来源字段跳过这些检查，并在元数据中写明；**不得伪造这些证据**。
- 每条数据的元数据必须包含：`source="fastsim"`、模型版本（如 `fastsim_kinematic_v1`）、全部动力学和噪声参数、随机种子、`time_base`。加载器能区分 fastsim 与 SITL 数据。

# 第三部分：分阶段任务

## 7. 第 0 阶段：摸底与设计备忘（不写实现）

1. 建立 worktree 和分支；确认 `Simulation-dev` 未被改动；
2. 查清：
   - 规划器输出的数据结构；
   - SITL 执行层（`runner_v3.py` 等）向分析层交付了哪些产物、各字段是什么；
   - 判定器和事实提取依赖哪些产物；
   - 哪些检查是 SITL 特有的；
3. 写一份不超过 2 页的设计备忘：适配层方案、需要跳过的检查及其方式、内核接口、参数清单、对现有代码的改动点（应尽量少，而且都不影响 SITL 路径）；
4. **停下汇报，等用户复核。**

## 8. 第 1、2 阶段：内核实现与校准

### 8.1 第 1 阶段：内核与适配层（无噪声）

1. 实现第 6.1、6.2、6.4 节；
2. 单元测试：
   - 速度、加速度、加加速度不超限；
   - 能到达航点；悬停时长正确；
   - 同一种子逐位可复现；
   - 输出帧数等于"仿真时长 × 10 + 1"；
   - 规划中的阶段事件全部产生；
3. 用三种意图、四种飞法各若干条规划跑通全流程（判定、事实、描述、导出、加载），确认标签和描述正常生成；
4. 测量生成速度（单进程每小时条数）；
5. SITL 路径回归：DR130 金标准、v0.5 示例加载、现有 CI 清单全部通过。

### 8.2 第 2 阶段：用 SITL 数据校准

**参照数据（只读）：**
- 首选 v0.6.1 的 T1、T4（共 84 次运行），时间轴已是仿真秒；
- 再加上 r2 的 465 次运行，用各运行自己的时钟模型把时间换算到仿真秒，换算方法沿用 T1 报告；
- 每次运行都有对应的规划结果，fastsim 用**同一份规划**重新飞一遍，逐运行配对比较。

**数据划分（防止过拟合）：** 按 family 把参照数据分成校准集和留出集（例如 r2 中 70% 的 family 用于校准；r2 其余 family 加上 T1、T4 用于留出评估）。参数只能在校准集上调整，留出集只评估一次。

**配对指标（逐运行、逐机）：**
1. 各阶段时长、总时长的相对误差；
2. 路径形状：fastsim 与 SITL 轨迹之间的平均横向距离、最大横向距离（按路径弧长对齐）；
3. 速度剖面：巡航段速度、转弯处最低速度、加减速段时长；
4. 真值最小机间距之差；
5. **标签层面：** 判定结果（任务成功、各条件）、运动模式槽位、可见事实、描述是否与 SITL 一致。这是最关键的一项。

**流程（遵守原则五第 2 条：先确认标准可行，再定标准）：**
1. 先用缺省参数跑一遍，报告第 1 到 5 项的分布，作为"未校准基线"；
2. 在校准集上调参，方法写清楚（网格搜索或简单优化），报告校准后的分布；
3. 根据基线和校准结果，**提出**第 8.3 节标准的具体数值。**停下，等用户和 Claude 确认数值后冻结参数和标准**；
4. 冻结后，在留出集上评估一次，报告是否达标。

### 8.3 拟定的通过标准（数值在第 2 阶段第 3 步确认）

| 项 | 拟定标准 | 理由 |
|---|---|---|
| 判定结果、运动模式槽位一致 | 两边都合格的运行中 ≥ 98% | 标签由同一套判定代码产生，轨迹足够像，标签就应一致 |
| 总时长相对误差 | 中位数 ≤ 5%，p90 ≤ 10% | 时序特征是早期识别的关键 |
| 平均横向距离 | 中位数 ≤ 1 m，p90 ≤ 2 m | 远小于机间距（7 到 12 m）和机动尺度（几十米） |
| 真值最小机间距之差 | 中位数 ≤ 0.5 m | 间距统计不应系统偏移 |

不要求逼近 SITL 两次运行之间的自然波动（毫米级），那是确定性仿真才有的水平，fastsim 不可能也不需要做到。

> **第 2 阶段结束：** 提交校准报告 `docs/fastsim_calibration_report.md`（含逐项分布、校准前后对比、留出集结果、冻结的参数），推送，以远端 CI 为准，打标签 `fastsim-v1-calibrated`（在 fastsim 分支上），**停下汇报。**

## 9. 第 3 阶段：扰动与噪声、小规模试产

1. 实现第 6.3 节；噪声参数先给出保守的缺省范围，写明依据（例如常见 GPS 精度、风速等级）；
2. 测试：
   - 噪声开启后，判定、事实、描述仍能正常生成；
   - 加入合理噪声后，标签不应大面积翻转。报告噪声强度从小到大时标签的变化曲线；
   - family 内三种意图的噪声参数完全相同（防捷径测试）；
3. **小规模试产：** 用 v0.6 生产的 profile（三种意图、300 个 family、900 个任务），在**与 SITL 数据不重叠的新主种子**下生成一批 fastsim 数据，报告：
   - 用时、合格率、各意图和飞法的计数、划分；
   - 与 SITL v0.6 数据集的统计对比（时长分布、速度分布、槽位分布）；
4. **停下汇报。**

## 10. 第 4 阶段：规模化生成（r3 结束后）

1. 多进程批量生成（每个进程负责一组 family，结果按 family 合并），断点续跑，进度文件，失败记录；
2. 目标规模由用户决定（例如 3 万条带标签的数据，以及用于自监督预训练的 10 万条以上无标注轨迹）；
3. 存储格式：先沿用现有 episode 格式。如果单条体积过大（例如总量超过 200 GB），提出一个更紧凑的格式方案（例如按 family 打包的 NPZ 或 Parquet），等用户决定，不要擅自改格式；
4. 在 README 的数据版本登记表中，为 fastsim 数据集单独登记一行：来源、模型版本、种子、规模、清单哈希；
5. **停下汇报。**

## 11. 数据使用规则（P0，写入数据契约）

1. **fastsim 训练数据与 SITL 评测数据的场景互不重叠：** 使用不同的主种子；导出时核对两者的 family ID 和场景参数哈希没有交集。否则同一个场景同时出现在训练和测试中，评测结果就会虚高。
2. fastsim 与 SITL 数据**不在文件层面合并**，由加载器按来源区分；
3. 论文与报告中，fastsim 数据一律标明"运动学仿真"，不得与 SITL 数据混称。

## 12. 停止条件（只列 P0）

1. `Simulation-dev` 工作目录、冻结归档或任何已有批次目录被改动；
2. SITL 路径回归不一致（DR130、v0.5 示例、现有 CI）；
3. 判定器、事实提取或描述模板需要为 fastsim 修改判定逻辑才能运行：停下说明，由用户决定；
4. 防捷径测试失败：噪声或场景参数在 family 内随意图变化；
5. fastsim 数据与 SITL 评测数据出现场景重叠。

## 13. 不做的事

- 不做 C++ 实现、GPU 并行、可视化界面（需要时另立任务）；
- 不模拟起飞、降落、碰撞、电池、传感器融合细节；
- 不新增意图、飞法或场景元素（这些在 fastsim 校准完成后，作为 v0.7 的内容另行规划）；
- 不改动 SITL 生产流程和已有数据。
