# 仿真提速前的时间基准审查（2026-10-11）

## P0：停止倍率实施

用户要求“导出网格按飞控源时间定义”和“倍率为 1 时与旧实现逐位一致”不能同时满足。现有 `analysis_v3.py:88–110` 用主机起止时间决定帧数，再按主机秒生成 10 Hz 网格；`observations.py:108–114` 和 `analysis.py:46` 将飞控源时间映射回主机时间。声明 `speedup=1` 不代表实际主机秒等于源秒。

对 pilot30b 四种飞法各取一条已完成、合格数据，只读其原有 `metadata.json`、`clock_models.json`。用已有 `mission_evaluation.source_time()` 的同一分段线性逆映射，对主机起止边界反求源时间，不外推。主机相对区间为 \([0,D_h]\)，仿真时长为 \(D_s=f^{-1}(D_h)-f^{-1}(0)\)，10 Hz 帧数为 \(\lfloor 10D\rfloor+1\)。这是边界和网格冲突的证据，**不是已实现的多机仿真时间轴**。

| pilot30b 任务 | 原主机时长/帧数 | 反求源时长/帧数（各机） |
| --- | --- | --- |
| patrol_0000_v00 | 168.814828 s / 1689 | 164.883820 s / 1649；164.933898 s / 1650 |
| rapid_passage_0000_v00 | 30.199197 s / 302 | 29.630471 s / 297；29.585131 s / 296 |
| reconnaissance_0000_v00 | 69.347858 s / 694 | 67.274183 s / 673；67.257412 s / 673 |
| reconnaissance_0001_v00 | 68.887904 s / 689 | 66.671141 s / 667；66.946676 s / 670；66.908184 s / 670 |

9/9 架次的帧数都发生变化。首条巡逻的模型斜率约 1.02497，实际含义为“主机秒/源秒”；倍率 2 理想斜率约 0.5，而不是 2。简单把主机时间乘声明倍率，在倍率 1 时仍不能满足严格源时间要求。多机源钟也需明确统一参考时钟及边界策略，不能默认为完全同步。

数值、run_id、原证据路径见 [v06_accel_time_conflict.json](v06_accel_time_conflict.json)。倍率参数、时钟窗口、参数门禁、记录器、分析器与判定器本轮均未改。B/C 不准备、不运行；A 保持旧 1 倍时间语义，仅用于并行因素对照。要继续倍率工作，需要先决定是否允许新时间契约改变旧数据结果及如何保留旧契约；本轮不擅自作此选择。
