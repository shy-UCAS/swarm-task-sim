## 1 停止事实与根因

**停止记录**（批次目录 `stop_report.json` 与 `control.json.stop_events`，两者一致）：

```
reason: state persistence failed: PermissionError: [WinError 5] 拒绝访问。:
        '...\v06_production900_seed2026100812\control.json.tmp' ->
        '...\v06_production900_seed2026100812\control.json'
utc:    2026-10-10T12:22:08.708087+00:00   （本地 05:22:08）
trigger_attempt_id: null
draining_attempts: []      completed_after_stop: ["a000293", "a000295"]
research_impact（控制器自述）: Unverified or interrupted evidence cannot support
        reproducible task outcomes; preserve all attempts for review.
```

**代码路径**（`swarm_sim/parallel_batch.py`）：

```python
44: def save_atomic(path, value):
        ...
51:         os.fsync(stream.fileno())
52:     temporary.replace(path)          # os.replace → MoveFileEx(REPLACE_EXISTING)，无重试
...
457:    def _persist(self, state):
458:        try:
459:            _save_state(self.root, state)
460:            return True
461:        except Exception as exc:
462:            reason = f"state persistence failed: {type(exc).__name__}: {exc}"
464:            _stop(state, reason)     # 一次性、不可逆：任何持久化失败都停止批次
467:            return False
```

**为什么重命名会被拒绝**：`os.replace` 在 Windows 上落到 `MoveFileExW(MOVEFILE_REPLACE_EXISTING)`；当目标文件被另一进程以**不含 `FILE_SHARE_DELETE`** 的方式打开时，该调用返回 `ERROR_ACCESS_DENIED(5)`。本仓库的读取函数正是这一类：

```python
36: def read(path):
        return json.loads(Path(path).read_text(encoding="utf-8"))   # CRT 默认共享，无 FILE_SHARE_DELETE
```

而 `scripts/run_parallel_batch.py:19` 显示**每个 worker 进程启动时都会读一次批次 `control.json`**（10.4 MB），控制器则在每次预留尝试前写一次（`parallel_batch.py:594` "Reserve global budget before Popen"）。

**已排除的原因**（逐项实测）：
- **ACL**：`SwarmData`、批次目录、`control.json` 的 ACL 均为 `Authenticated Users: Modify` 等**只有 Allow、无 Deny**；`control.json` 属性为普通 `Archive`，非只读。
- **杀毒/实时防护**：`WinDefend` 服务 **Stopped**，`RealTimeProtection=False`、`AntivirusEnabled=False`、`BehaviorMonitor=False`。
- **磁盘/文件系统**：`Get-Volume F` 健康、NTFS、剩余 840 GiB；05:15–05:30 **无任何 disk/NTFS/volmgr/Defender 系统事件**。
- **worker 侧**：296 个 `worker.log` 中**无**任何 `PermissionError`/`WinError 5`/拒绝访问记录。
- **是否我的监控读取造成**：我的只读进度监控每 25 分钟读一次 `control.json`，第二段的读取时刻为 05:02:14 与 05:27:14，**与 05:22:08 的失败不同时**；第一段 20 次读取与本次全部成功保存也未见冲突。它在**结构上**属于同一类"无 FILE_SHARE_DELETE 的读者"，但**不是本次失败的时刻来源**。

**结论**：这是一次**瞬态**的写-读竞争/共享占用（存活候选：Windows Search 索引器 `WSearch` 处于 Running，以及任何此刻打开该文件的读者），被无重试的原子替换放大为不可逆停止。**证据表明失败是瞬态的**：停止路径自身在 2 分 44 秒后（05:24:52）对同一路径 `save_atomic` **成功**并落盘了含停止记录的最终台账；无 `.tmp` 残留。

**这项问题会让哪一项研究结果出错**：不会让**已完成的 296 次运行**的任何轨迹、标签、语义或质量结论出错（每次尝试都有独立证据，见 §5–§9）。它使 **v0.6 正式生产数据集（900 任务、含 train/validation/test 划分与中文描述）不存在**——`finalize` 要求 `completed=true`，因此任何"v0.6 正式生产数据集已完成/可用于训练"的表述都是**错的**；第 ⑧ 项的导出划分、描述层与清单哈希无法产出。
