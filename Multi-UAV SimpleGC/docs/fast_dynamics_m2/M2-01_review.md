## 3. 必须修复的路径行为

### R1 [P1]：默认输出根实际在仓库内部，默认入口不可用

位置：`swarm_sim/fast_dynamics/output_policy.py:44`，第 46 行：

```python
return repository_root() / DEFAULT_PARENT / DEFAULT_LEAF
```

当前仓库为 `.../Simulation-dev`，返回了：

```text
实际：.../Simulation-dev/SwarmData/fast_dynamics
要求：.../SwarmData/fast_dynamics
```

这是仓库子目录，不是同级目录。随后 `assert_new_external_path` 正确拒绝它，导致文档中的默认命令失效。

独立复现（清除当前进程的 `FAST_DYNAMICS_OUTPUT_ROOT`，不改变系统环境）：

- `run_fast_dynamics.main([fixture])` 返回 `SystemExit(2)`，报 `attempt path must stay outside the repository`。
- `verify_fast_dynamics_m01.main()` 无输出参数时同样返回 `SystemExit(2)`。
- `resolve_output_root(env={})["inside_repository"]` 为 `True`。

测试遗漏原因：现有测试只断言路径末两段是 `SwarmData/fast_dynamics`，没有断言相对于 Git 根的正确父子关系，也没有执行默认入口选择路径的分支。

**正确目标：** 默认根相对于实际 Git 根的父目录生成，解析后位于仓库外。测试用独立预期路径与默认入口行为验证；不要用调用被测函数再生成预期的方式自证正确，不硬编码当前仓库名来代替位置校验。

### R2 [P1]：所选输出根只是元数据，根外输出和 run-id 路径逃逸仍被接受

位置：`output_policy.py:87` 的 `assert_new_external_path`、第 119–127 行的新 attempt 命名，以及三个入口传递的参数。

当前校验只证明目标在仓库外；没有证明它在 `--output-root` / 环境变量 / 默认选定的根之下。两项独立复现：

1. 指定 `--output-root <review_02>/selected_root`，同时指定 `--output <review_02>/outside_selected_root/attempt`，入口接受并实际写入输入、配置、attempt 和失败标记。审阅把 `run_mission` 替换为明确哨兵异常，没有为该复现进行真实飞行仿真；因此能证明路径错误发生在模拟之前。
2. `new_attempt_path(selected_root, "x/../../../escaped")` 生成的路径经校验后仍被接受，解析目标不在 selected_root 内。此项只检查路径，没有创建逃逸目标。

这与 M2-01“输出只能进入外部根”的要求不符，也会让产物记录的 `output_root` 与实际位置不一致。仅拒绝仓库路径不能完成这项要求。

**正确目标：** 三个入口使用同一个已解析且合格的有效根；创建任何目录/文件前，同时校验目标在仓库外、在该根之下、是新目标。拒绝使新 attempt 逃逸的 run-id/前缀路径片段。保持根优先级为显式参数 > 环境变量 > 合法默认根，拒绝不能使用的根配置，不以硬编码机器路径修复。

必须同步核对上层到下层的根传递：`verify_fast_dynamics_m01.py:94` 和第 109 行调用 `run_pipeline` 时只传 `--output`，没有传上层选定根。严格根约束后若不同时修复，会使自定义根的完整验证链失败。现有 M1 测试的 CLI 临时路径也应显式提供隔离根，不能通过放宽生产策略维持测试。

若保留 benchmark 的无参数 stdout 历史行为，应明确该分支不生成文件；一旦选择文件输出，根约束必须一致。不要借此扩大到 M4 调度或改变公共 `write_episode/build_dataset/load_episode` 的旧 API 契约。
