# v0.5 验证运行选例门禁：停止报告

状态：**BLOCKED**。M0、H、R、T、M、P、DR、L 已按修订版 r1 顺序完成各自的离线门禁；本报告在验证运行选例时触发第 11.1 节场景不可满足的问题，故**没有启动 v0.5 SITL，也没有进入 HD 或试生产；尚未达到暂停 1**。没有更改正式 profile、采样种子、规划参数、时间容差或间距阈值。

## 阻断证据

第 11.1 节要求 VR2 为“侦察、4 机、集群编队”，且验证场景从正式 profile 的候选中选取。固定 profile 的 DR manifest（SHA256 `5a1f7951cb8e1c803c767c13785cfb061fce570ecf43f4ec5b22ff8ef0ce81e6`）含 383 个候选，其中 **64/383** 是 4 机集群。64 个对应侦察任务的规划结果为 **0/64 可行、64/64 被拒绝**，原因全部是 `time-aware nominal routes too close`。其中 5/64 个候选的巡逻任务可规划，但这不能替代 VR2 的侦察任务。被接受的 130 个双意图场景中也没有 4 机集群。

| 验证场景类型 | 正式候选中已规划任务数 | 当前结论 |
| --- | ---: | --- |
| VP1：3 机、巡逻、K=2、返航、hold=0 | 17 | 可选源 |
| VP2：4 机、巡逻 | 19 | 可选源；与预筛选下限的距离仍须按选例规则记录 |
| VP3：2 机、巡逻、K=3、不返航 | 16 | 可选源 |
| VP4：VP1 同场景与任务采样，仅 hold=1 | 0 个现成任务 | 有 VP1 来源；需另作离线复制与可行性核查，本轮未到此步 |
| VR1：3 机、侦察、东/西进场、auto 轴 | 9 | 可选源 |
| **VR2：4 机、集群编队、侦察** | **0** | **阻断** |

两套独立的只读审计分别见 [`validation_preflight_v3.json`](../tmp_v05/validation_preflight_v3.json) 和 [`validation_preflight_independent.json`](../tmp_v05/validation_preflight_independent.json)。前者可由 `scripts/preflight_v05_validation.py` 对固定 DR manifest 复算；后者额外核对了相关候选任务 SHA256，并分别统计全部候选和 130 个双意图接受场景。详细 DR 可行率、拒绝原因与 4 机选择偏差见 [DR 报告](v0.5_dr_review.md)。

## 已完成工作与证据边界

WP-L 已实现版本化事实抽取、双通道事实核对、中文模板与描述一致性校验、独立 `describe` 导出及[数据契约](data_contract_v0.md)。L01–L07 全部通过；全套离线测试 **499/499** 通过，保护文件 **11,307/11,307** 哈希不变，见 [L 报告](v0.5_wp_l_offline_report.md)。DR 的联合可行率为 **130/383 = 33.94%**，满足其写定门槛，但 DR 门槛并未保证 VR2 类型可用。上述结论分别来自合成语义测试、历史日志只读核查、纯规划和静态候选审计；**均不等于本轮实际 SITL 验证**。

本轮停止在验证场景选取之前。按第 0 节“验收项不通过即停止”和不擅自更改 profile/参数的规则，不能把 4 机线队、巡逻可行的 4 机集群、或规划失败的侦察任务充作 VR2。后续若修订 VR2 的场景条件或修订正式 profile，应先明确新的验收定义、指纹与需要重做的 DR 范围，再继续验证运行。当前 SITL 预算消耗 **0/8**，试生产预算消耗 **0/22**。
