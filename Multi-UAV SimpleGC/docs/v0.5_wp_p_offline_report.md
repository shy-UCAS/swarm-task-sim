# v0.5 WP-P 离线里程碑

状态：**WP-P 离线门禁通过，具备进入 WP-DR 的代码条件**。按[修订版 r1 计划](swarm-task-sim_v0.5_最小双意图数据集实施计划_修订版r1.md)第 7、14 节接入第二意图“巡逻”；本阶段未运行正式 DR 或 SITL，因而不把名义间距与名义耗时当作实飞验收。

生产注册表现包含侦察、巡逻两个意图和对应规划器。巡逻 TaskSpec 只接受规范化参数 \(K\in\{2,3\}\)、边界偏移 0 m、小段 5 m、访问半径 3 m、重访间隔系数 2，并绑定 `staggered_same_loop_v1` 与 `semantic_phase_route_v1`。规划器按任务种子选顺/逆时针、沿周长 \(P\) 每 \(P/N\) 布置入环点，枚举全部 \(N!\) 种分配。每个可行方案均经接近、巡逻、返航三个阶段的完整时间感知间距判据；按总接近距离最短、同距编号字典序选定。预筛选、通用判据失败、全部分配不可行保留不同拒绝原因。航线去零长度、每阶段每机 100 航点上限与 schema 2 路由编译继续执行。

巡逻阶段的各分配通常只是同一组入环轨迹的机号置换，因此在**所有机到所有入环点的接近航段都不会被清成 no-op**时，复用一次完整判据的通过结果；选中方案重新计算带正确机号的诊断。若存在距入环点小于 0.05 m 的起点，则退回逐分配完整检查。规划元数据记录缓存资格、完整调用、复用及诊断复算次数。[独立对照](../tmp_v05/p/patrol_cache_comparison.json)中两种分配的 \(\tau=5\) s、最小间距 30 m、阶段时长 93.833 s、33,476 个点对完全相同；正常路径完整巡逻检查 1 次、复用 1 次、选中诊断复算 1 次，近点 no-op 回退路径检查 2 次、复用 0 次。

新 generation profile 可选 `sample_laps: [2,3]`，抽取结果在场景编译前写成明确的 K；若抽中 3 圈且名义巡逻运动耗时超过 180 s，改选 2 圈，并记录原抽取、最终值及原因。手工 TaskSpec 可以明确指定 3 圈，条件不满足时规划器拒绝。没有该 profile 字段的旧生成路径保持原行为；TaskSpec 任务种子与模板身份无关的核验见[M0 基线](v05_m0_baseline.md)。

验证器 `perimeter_revisit_v1` 在 SIM、FCU 两个通道分别计算小段访问次数与初始、内部、末段最大间隔，记录群级访问、每机可证实圈数、首次边界覆盖和首次完整圈时刻。证据缺口保持三值未知；群级达到次数不伪造每机圈数。结果接入语义验证、行为标签及审计。新任务统一绑定 `multi_intent_validation_v2`、`multi_intent_execution_limits_v2`；旧 v0.4 同协议数据集继续可加载，新旧协议混导被拒绝。版本选择、执行附件和任务绑定检查见[协议测试](../tests/test_wp_p_protocol.py)。
