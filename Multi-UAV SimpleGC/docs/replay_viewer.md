# 离线回放与计划预览界面

第一版桌面界面使用 PyQt5 + PyQtGraph，读取已有任务和历史记录。它不启动 SITL、不连接 MAVLink、不修改原始数据，也不重新计算任务成功或数据资格。

## 启动

在 `Multi-UAV SimpleGC` 目录使用 PowerShell 7：

```powershell
conda run -n llm --no-capture-output python replay.py
```

也可以在 PowerShell 7 中运行工程内的 `启动回放界面.ps1`。脚本读取当前工程 `.conda-env`；不会安装包或切换到 base。

启动后优先加载本轮正式三机历史记录；若该记录不在当前电脑上，则打开三机任务计划。默认暂停，点击“任务开始”可跳过就绪等待，再点击“播放”。

指定任务或场景：

```powershell
conda run -n llm --no-capture-output python replay.py missions/recon_shared_3uav.json
conda run -n llm --no-capture-output python replay.py scenarios/recon_shared_3uav_v03.json
```

指定一次历史运行目录：

```powershell
conda run -n llm --no-capture-output python replay.py "verification/v03_integration_20260930/runs/recon_shared_demo_3uav_20260930T152031Z_08eff45d"
```

## 界面操作

| 操作 | 用途 |
|---|---|
| 打开任务 / 场景 | 读取 TaskSpec v1/v2 或执行场景 JSON，校验并预览路线；不启动仿真 |
| 打开运行目录 | 选择包含 `metadata.json`、`scenario.json`、`samples.csv` 的已结束运行 |
| 记录列表 / 加载记录 | 从当前工程 `runs/`、`verification/` 中选择已有运行；列表选择后点击加载 |
| 三机示例 | 打开正式三机记录，或回退到三机任务计划 |
| 播放 / 暂停 | 播放已有记录，到末尾自动暂停，再播放则从开头开始 |
| 回到开头 / 任务开始 | 跳到运行起点或第一条 `phase_start_sent` 事件 |
| 时间轴 / 秒数输入 | 拖动或精确定位；拖动时间轴时暂停播放 |
| 0.25×～8× | 调整回放速度，原始时间戳与数据不变 |
| 飞机复选框 | 分别隐藏某架飞机的分区、计划、轨迹和高度曲线 |
| 计划虚线 / 责任分区 | 显示或隐藏计划图层 |
| 历史尾迹 / 显示全程轨迹 | 默认只显示当前时刻之前的尾迹；可切换为整次运行的轨迹概览 |
| 适应全图 | 按计划、责任区与实际轨迹重新调整视野 |
| 执行事件 | 双击某条事件跳转到对应时刻 |

中央地图是局部 ENU 坐标，横轴向东、纵轴向北，单位为米，保持等比例。方框表示生成点，虚线表示计划路线，实线表示记录的轨迹，圆点表示当前有效位置。鼠标可缩放和平移。

底部高度曲线始终展示全程，竖线对应当前回放时间。不同飞机共用同一颜色；高度接近时曲线会重叠。高度是相对公共 ENU 原点的 Up，不是测距仪离地高度；就绪前的原始估计也可能出现跳变，界面保留记录而不修饰。

右侧显示最近有效样本的高度、三维速度大小和解锁状态，悬停表格可查看样本时刻与飞行模式编号。阶段标题取自最近执行事件及其语义映射，不是从轨迹推断的群体意图。

## 显示数据的含义

- 回放读取 `samples.csv`，包含准备、起飞、任务和降落；时间直接使用相对运行启动的主机秒数，与 `events.jsonl` 对齐。不会把任务窗口的 `observations.csv` 当成同一起点的数据混入。
- 圆点使用回放时刻之前的最近样本，不做位置插值；样本无效或距离其采样时间超过 `max_gap_s` 时隐藏圆点、表格显示“缺失 / 过期”。历史尾迹保留已有证据，无效点和长缺口处断线。
- 淡色矩形表示计划责任区，**不代表已经覆盖**。第一版不计算覆盖动画、不显示实时遥测，也不叠加 SIM 真值轨迹。
- “任务 / 结果”页读取 `analysis_latest.json` 指定的已保存分析，明确标为最终结果。它不是播放到当前时刻的结果，也不是本界面重新计算或重新进行完整哈希审计的结论。
- 缺失或损坏的可选结果文件会产生读取提示，不用计划推断成功。`scenario.json` 与 metadata 中的场景矛盾、同机时间重复或倒退、未知 agent 等输入会拒绝加载。
- 支持失败运行的回看；缺少采样文件时仍可展示场景和失败原因，但没有轨迹可播放。仍标记 `running` 的目录不接受，避免把未结束记录当成完整回放。
- v1 任务保留计划和轨迹查看能力；共享责任分区来自 v2 元数据，不会给 v1 虚构公共分区。

## 实现结构

`replay.py` 是独立入口。`replay_viewer/data.py` 使用标准库读取和校验回放数据；`replay_viewer/window.py` 负责 Qt 界面、后台文件读取和图形展示。界面没有导入飞控运行器，没有新增飞控控制通道。新增模块位于独立包，不改变此前冻结的 `swarm_sim/*.py` 运行代码。

当前 `llm` 环境中的 PyQt5 5.15.10、PyQtGraph 0.13.7 与 NumPy 已验证可用；本轮未安装依赖。`requirements-gui.txt` 单独列出可视化依赖，核心命令行不强制依赖 Qt；文件中的版本范围不等于所有组合都经过测试。

## 验证与范围

验证覆盖：无效点、长缺口、重复/倒退时间、未知身份、准备期时间原点、失败记录、矛盾场景、可选结果损坏、只读性，以及 Qt 播放/暂停、倍速、拖动、末尾停止、隐藏飞机和切换计划。

`scripts/verify_replay_gui.py` 加载上一轮 5 条正式矩阵记录和 10 条试生产记录，覆盖 2/3/6 机和受控失败；比对关键原始文件读取前后 SHA256，并实际生成界面截图。此验证不启动新的 SITL。

本轮全套 150 项测试通过，结果见 `replay_gui_tests.txt`；真实日志加载结果和截图位于 `../verification/replay_gui_v01_verified/`。截图使用 Qt 离屏渲染；Windows 离屏插件未提供系统字体时，仅加载本机已有微软雅黑字体，不下载字体。

后续可在该界面上增加实时监看、受控运行管理、覆盖动画、SIM 对照与三维视图。当前加载器将单次记录读入内存，已验证本工程小规模运行；超长日志的分页和后台索引尚未实现。
