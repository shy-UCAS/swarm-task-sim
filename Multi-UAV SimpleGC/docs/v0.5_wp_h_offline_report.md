# v0.5 WP-H 离线里程碑：机载驻留参数

WP-H 离线部分通过。新增 `execution.hold_semantics = "integer_seconds_v1"` 时，规范化只接受非负整数秒；不写该字段的 v0.4 任务沿用原行为，16 个冻结示例与 V06 任务的规范化哈希均未变化。分析现在按飞机、语义阶段及任务内序号对照任务项 `param1` 与 BIN `CMD.Prm1`；整数语义下，缺证据或不一致均不能获得合格资格，旧语义仅记录诊断。

## 已观察到的事实

- v3 上传链路是 `route_mission_for` → `Vehicle.upload`。每个阶段清空并重传任务，HOME 为 seq 0、速度命令为 seq 1、路线 NAV_WAYPOINT 自 seq 2 起。中间 NAV 的 `params[0]` 为 0，末 NAV 为 `terminal_hold_s`。`Vehicle.upload` 把 `params` 原样放入 `MISSION_ITEM` 或 `MISSION_ITEM_INT` 的 `param1`；消息类型由飞机发来的 `MISSION_REQUEST` 或 `MISSION_REQUEST_INT` 决定。历史原始包中实见 `MISSION_REQUEST`。Python 侧并未把 0.5 改为 0。
- 从原始台账枚举了 15 个 v0.4 route 运行和 2 个 WP-S spike 运行；未把 `tmp_v04` 中的副本重复计数。16 个完成运行的 **515/515** 个 NAV 项可逐项定位：356 个中间项为上传 0 → `CMD.Prm1=0`，159 个末项为上传 0.5 → `CMD.Prm1=0`。另一个原有失败运行的 33 项没有充分上传/机载证据，标为 `unknown`，保留原失败结论。详细逐项记录见 [普查 JSON](../tmp_v05/h/v04_route_param_census_final.json)。
- 已配对的 515 个 `CMD` 在对应飞机、阶段的上传开始之后 (0.0188)–(1.0939) s 出现；相对上传完成时间，范围为提前 (0.0703) s 至滞后 (0.0541) s。全部处在生命周期时钟模型的观测范围内，无需外推。诊断采用上传窗前后各 (0.2) s 的归属余量；若两个阶段的余量窗交叠并使同一包可归属两处，结果为 `unknown`。

上述现象支持“非整数秒在上传后、写入机载任务记录前发生转换”的推测，也与整数化处理相符。它不能区分 MAVLink 接收、固件内部存储、BIN 记录等具体环节，更不能证明飞控实际驻留了多少秒。当前历史样本只有末点 0.5 s，缺少末点 1 s 的机载对照；VP4 仍须实测 `Prm1=1`，并按计划 11.2 节完成 HD 决定。

## 实现和验收

分析附件为 `onboard_mission_param_check.json`，版本 `onboard_mission_param_check_v1`；其哈希列入分析 `manifest.json`。`quality.json` 与 manifest 同时记录版本、`pass`/`mismatch`/`unknown`、是否启用整数语义及门禁结果。新语义若无 BIN、无可用非外推时钟映射、上传时间窗不完整、机载项缺失或内容冲突，会明确降为 `unknown` 或 `mismatch`，并使新运行的资格为 false。旧语义出现历史 0.5 → 0 的不一致时只作为诊断记录。

H01 检验两个控制模式的合法整数、非整数与非法数值以及缺字段的旧行为；H02 核对全部 16 个冻结规范化哈希；H03 覆盖同序号跨阶段、跨飞机、交叠上传窗、缺 BIN、缺项、冲突、错误 `CTot`、附件哈希及门禁一致性。新增 7 项测试通过；全套 **437/437** 通过，原 430 项保持通过。M0 的 **11,307** 个受保护文件哈希复核为缺失 0、改变 0，记录见 [保护复核](../tmp_v05/h/protected_check.json)。本阶段没有启动 SITL。
