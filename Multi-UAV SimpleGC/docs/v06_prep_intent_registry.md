1. 老仓库归档（`Simulation`，提交 `8eaf583b`）**只读**。可以读取其中的 v0.5 数据做对照，所有输出一律写到 `SIM_DATA_ROOT` 下。

## 1. 截断扰动诊断（先做，不改运行代码）

**目的：** 确认 v0.5 的成功判定、可见事实和描述，都是在轨迹上**测量**出来的；规划结果只起参考作用。v0.5 合格样本中两种意图的成功率都是 100%，归档里没有"没做到"的反例，所以光看归档结果，无法知道判定器在没做到时会不会给出否。这项诊断保护的是：标签和描述的事实正确性。算法线正在使用这些标签。

**样本：** 从归档中只读选取 4 次合格运行：

- 巡逻 2 次：一次 3 圈且要求返航，一次 2 圈；
- 侦察 2 次：至少一次要求返航。

**做法：** 在内存中复制轨迹并截断，直接调用现有的验证、事实提取和描述生成函数。不修改任何文件或哈希绑定；如果文件级流程拒绝截断后的输入，就绕过文件层，直接调用这些函数。结果写到 `SIM_DATA_ROOT`。

每次运行做两种截断：

| 截断位置 | 预期 |
|---|---|
| a. 主任务进行到约一半 | 意图成功为否或未知；巡逻观测圈数小于原值；描述不再声称完成原圈数 |
| b. 主任务完成后、返航开始前（只对要求返航的运行做） | 意图成功可以保持为真；返航成功为否或未知；描述不声称已返航 |

"否"和"未知"都可以接受，汇报中写明给出的是哪一个。

**汇报：** 列出运行编号，并给出一张表：每种截断下，原值与截断后的成功判定、返航判定、观测圈数和描述相关句子。

**结果处理：**
- 全部符合预期：继续第 2 节，不需要暂停。
- 任一字段在轨迹不支持的情况下仍保持规划值：按第 7 节停止。

## 2. 意图包与注册表

一个意图包包含 5 个组件。下面的名称和类型仅为示意，执行方可以按现有代码调整，但**输入和使用规则不能改**：

```python
@dataclass(frozen=True)
class Style:                      # 一种飞法
    name: str                     # 描述性名称，如 "equal_strip_lawnmower"
    version: str
    plan: Callable[[MissionSpec], Plan]

@dataclass(frozen=True)
class IntentPack:
    name: str
    sample_params: Callable[[Rng, SharedParams], IntentParams]  # 只采样本意图特有的参数
    styles: dict[str, Style]                                     # 至少一种
    verify: Callable[[Trajectory, MissionSpec, PlanReference], VerifyResult]
    verifier_version: str
    extract_facts: Callable[[Trajectory, MissionSpec, PlanReference], Facts]
    facts_version: str
    templates: TemplateSet        # 训练组、测试组、版本号

REGISTRY = {
    "recon":  RECON_PACK,
    "patrol": PATROL_PACK,
}
```

### 2.1 共用参数

共用参数由框架采样，意图包不得重新定义速度、机数、进场方向、是否返航等共用参数的取值。摸底已确认 v0.5 两种意图共用同一套采样，保持现状。

### 2.2 规划参考的使用规则（r2 修订）

验证器和事实提取接收三样输入：轨迹、`MissionSpec`、规划参考（只读）。

**可以用规划参考做的事：**
- 划定时间窗口，即决定看轨迹的哪一段；
- 充当匹配模板，例如巡逻路线节点；
- 核对任务与场景的绑定是否完整。

**不可以做的事：**
- 任何输出字段直接取规划值，例如计划圈数、名义时刻、名义覆盖率；
- 观测不足时用计划值补全。观测不足时，结果必须是"否"或"未知"。

### 2.3 阶段角色词表

规划结果中的阶段角色（例如进场、主任务、返航）由框架统一登记，现有代码中已在使用的角色名照原样登记。每种飞法、每个意图的规划器都必须用这个词表标注阶段。验证器按角色取窗口，不按飞法取。

## 3. 多种飞法（对应用户确认 ②）

- 每个意图包至少登记一种飞法。v0.5 的侦察、巡逻各登记一种：`equal_strip_lawnmower`、`staggered_same_loop`。
- 任务清单中的每个任务都记录：意图、飞法，以及四个组件的版本号（规划器版本即飞法版本、验证器、事实提取、描述模板）。
- 飞法在冻结清单时由清单生成器决定：
  - **只有一种飞法的意图，不得消耗随机数**（否则 v0.5 的种子序列会变）；
  - 有多种飞法时，用独立的随机子流抽取，不影响其他参数的抽取。
- 飞法只作为元数据导出，不放进模型输入字段。
- **验证器不得按飞法分支。** 同一意图无论怎么飞，"任务是否完成"的判据都相同。

---

## 4. 由框架强制执行的规则

1. **观测性约束（r2 修订）：** 验证器和事实提取的输出必须来自轨迹测量（第 2.2 节），由截断扰动测试强制（第 6 节第 3 项）。
   - r1 中的静态导入检查取消。原因：导入链经过注册表，必然能到达规划器，这项检查说明不了任何问题。
2. **注册时检查：**
   - 每个意图包的组件齐全，版本号非空；
   - 训练模板组和测试模板组都不为空，且两组之间没有相同的句式（保护模板划分不泄漏）；
   - 规划器输出的阶段角色都在角色词表内。
3. **共用参数对比表（诊断项，不阻塞）：** 清单冻结后自动输出一张表，对比各意图的速度、机数、进场方向和预计时长分布。预计时长不同是已知情况，留给 v0.6 正式内容处理。

## 5. "快速通过"纸面核对（对应用户确认 ①）

**已确认的定义：** 从区域一侧进入，路径直接穿过区域，从另一侧离开；不停留、不绕圈；速度与其他意图共用同一套取值，不用更快的速度来体现"快速"。

只写一份不超过一页的核对说明，放在 `docs/` 下，**不写实现代码**。逐项回答：

1. 五个组件各自需要做什么（每项一两句）。验证器的判据只列名称（例如：进入区域、从对侧离开、区域内无停留、无绕圈），**不定阈值**。
2. 新增它是否只需要：一个新的意图包、注册表一行、描述模板。如果需要改框架，列出改哪里、为什么。
3. 重点核对：
   - **返航要求：** 摸底确认"是否返航"在同一 family 内共用，取值为真或假。快速通过在要求返航时怎么飞回去：原路穿回、绕开区域，还是其他方式？原路穿回看起来像"第二次通过"，有语义歧义。如果改为禁止返航，就会打破 family 内共用，"不返航"本身就会成为识别快速通过的捷径。列出可选方案及各自的问题，不做决定。
   - **阶段角色：** 现有的角色词表是否够用，"离开区域"是否需要一个新角色。
   - **任务结束：** 不返航时停在对侧离开点，这与现有的"停在主任务末点"语义是否一致；轨迹记录截止在哪里。
   - 进入侧和离开侧能否由共用的进场采样决定。
4. 列出它可能带来的捷径风险（例如总时长明显短于其他意图），只列出，不处理。

## 6. 测试

1. **规划等价性：**
   - 先以 `fe7ac4d` 为基线（在改动运行代码之前），用重构前的代码完整生成 DR130（主种子 `2026100205`），分别与归档中实际使用的 PP20 清单和 B240 清单逐任务比较。控制器加上的封装字段（pilot_index、batch_index 等）按其构建方式单独精确核对。
   - 然后把重构后代码的规划结果，与重构前逐任务比较规范化 JSON 的哈希，必须完全一致。比较时排除本次新增的飞法和版本号字段。
   - 金标准以哈希列表的形式存为测试夹具（小于 5 MB），可以进 CI。
2. **标签与描述等价性（本地测试，不进 CI）：** 在归档的运行上（只读，按 `analysis_selections.json` 选用正式分析），分别用重构前后的代码计算，必须完全一致，并且与归档记录一致。分母分开报告：
   - 成功判定和槽位标签：260 次；
   - 描述：252 次运行、1008 条。
3. **截断扰动测试：** 把第 1 节的诊断固化为本地测试。如果能从规划结果生成理想轨迹，并直接调用验证器和事实提取，就另做一版**遍历注册表**、可以进 CI 的测试；如果做这一版需要大量伪造分析产物，就只保留本地版本，并在汇报中说明。
4. **随机数隔离：** 测试中临时给侦察加一种假的第二种飞法，所有任务的种子、family、划分和共用参数都不变，只有飞法字段不同；去掉后与 v0.5 清单完全一致。
5. **注册检查：** 缺组件、版本号为空、训练组与测试组模板重叠、阶段角色不在词表内，四种情况都会被拒绝。写成遍历注册表的形式，以后新增的意图包会自动受检。
6. 分片并行的全部测试继续通过，并确认分片执行路径确实经由注册表调用意图。
7. 本次改动涉及的模块，如果原有的单元测试不依赖数据，纳入 CI。

## 7. 停止条件（只列 P0）

1. 归档目录有任何改动。
2. **重构前后结果不一致**（第 6 节第 1、2 项）：说明重构改变了行为。只花一轮定位原因，然后停下汇报。不得通过修改金标准或放宽比较来让测试通过。
3. **重构前的代码与归档记录不一致**（第 6 节第 1、2 项中与归档的比较）：说明冻结数据无法由其自身代码复现。只花一轮定位原因，然后停下汇报。
4. **（r2 修订）截断扰动中，任一成功判定、可见事实或描述在轨迹不支持时仍保持规划值：** 意味着 v0.5 的标签或描述报告的可能是"计划"而不是"观察"。停下汇报。
5. 注册检查发现 v0.5 的训练模板组与测试模板组存在重叠：停下汇报。

其他发现写进汇报，继续工作。
