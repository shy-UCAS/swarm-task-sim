# 第二部分：本次任务

## 6. 为什么要改

现有设计中，**任何规则停止都不可恢复，而收尾（finalize）又要求全部任务完成**。结果是：一次与研究无关的环境意外，就会让十几个小时的运行无法收尾。r1、r2 都是这样丢掉的。

**滚动异常规则**（最近 20 次中有 5 次异常即停止）的作用，是在质量开始漂移时**停止派发**，避免在出了问题的环境里继续产出废数据。这个作用用"暂停、等人检查后续跑"同样能实现：
- 不合格的运行本来就会被质量门禁剔除，不会进入数据集；
- "不可恢复"这个后果，并没有比"暂停"多保护任何研究结论。

**确认违规类的停止保持不可恢复**：它们说明系统本身可能出了问题，不能简单续跑。

## 8. 改动内容

### 8.1 停止规则分两档（`swarm_sim/parallel_batch.py`）

**A. 不可恢复的规则停止（保持现有行为，不改）：**
- 确认违规：真值最小间距、机载任务参数确认不一致、起飞前参数或固件门禁、受保护文件哈希变化；
- 台账保存重试用尽、派发基础设施失败；
- 合并时任务重复或遗漏、family 跨划分泄漏（收尾阶段）。

**B. 滚动异常改为"规则暂停"：**
1. 触发条件不变：最近 20 次中异常达到 5 次（异常的定义不变）。
2. 触发后：停止派发新任务，在飞任务照常降落、收尾、登记。
3. 台账记录：`paused=true`；`stopped_reason` 保持为空；在暂停事件中写明 `kind="rule"`、`pause_reason`（触发时窗口内的全部异常运行，逐条列出运行编号与异常原因）、触发时刻、触发的尝试编号、排空后完成的尝试。现有的人工暂停事件写明 `kind="manual"`。
4. 允许用 `run --resume` 续跑，与人工暂停的续跑路径相同；续跑事件记录在台账中。
5. **续跑后滚动窗口连续计算，不清零。**
6. **续跑后的再次触发规则必须明确：** 只有当**新登记的运行本身是异常**、并且登记后窗口内异常数达到 5 时，才再次暂停。续跑后如果下一次是正常运行，即使窗口里仍残留着之前的 5 次异常，也不触发。否则批次续跑后会被旧记录立即再次暂停，永远跑不下去。
   - 请核实：在第一次暂停之前，这条规则与现有行为**完全等价**（因为异常数只会在登记异常运行时增加）。在汇报中说明核实结果。
7. 规则暂停次数不设上限，每次都需要人工续跑；台账记录累计的规则暂停次数。

### 8.2 `progress.json` 与 `status`

- `progress.json` 增加 `pause_kind`（`manual` 或 `rule`）、`pause_reason` 摘要、累计规则暂停次数。
- `status` 命令的输出能区分"人工暂停""规则暂停""规则停止"三种状态。

### 8.3 资源采样增强

命令文档中的资源采样块，在现有整机 CPU、内存之外，每次额外记录**内存占用前五名和 CPU 占用前五名的进程**（名称、PID、占用量）。输出写在批次目录之外。目的是规则暂停时能直接看出是哪个进程在抢资源。

### 8.4 命令文档（`docs/v0.6_formal_run_commands.md`）

1. 增加"规则暂停后的处理流程"一节：
   - 读 `progress.json` 和台账中的 `pause_reason`，确认触发的运行及原因；
   - 查看资源采样，确认是否有外部进程抢占资源；
   - 排除原因（例如关闭无关程序）后，再用 resume 续跑；
   - 如果原因不明或无法排除，不要续跑，交给用户决定。
2. 写明：**生产期间机器应独占使用**，不运行可视化播放器、本地大模型、文档解析服务、模型训练等程序。
3. 生产命令块暂不改批次 ID（新批次在下一轮测试后确定），但续跑的说明要覆盖规则暂停。

### 8.5 测试

1. 滚动异常达到阈值 → 状态为规则暂停（`paused=true`、`stopped_reason` 为空、`kind="rule"`），停止派发，在飞任务收尾并登记。
2. 规则暂停后续跑：任务不重不漏，预算连续，滚动窗口按完整完成顺序连续计算。
3. 续跑后下一次是正常运行 → 不再次暂停；续跑后再出现一次异常、窗口内异常达到 5 → 再次规则暂停；累计次数为 2。
4. 确认违规类、台账保存重试用尽 → 仍为不可恢复的规则停止，`--resume` 被拒绝。
5. 人工暂停（Ctrl+C）的行为不变，`kind="manual"`。
6. `progress.json` 和 `status` 正确区分三种状态。
7. 原有全部并行测试、DR130 金标准回归、v0.5 示例加载测试通过；新测试加入 CI 清单。
