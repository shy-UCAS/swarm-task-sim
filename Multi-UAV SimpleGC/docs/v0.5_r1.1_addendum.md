# v0.5 修订版 r1.1：场景采样与验证选例补充

本补充依据用户在 v0.5 DR 构成诊断后的决定执行；除以下变更外，修订版 r1 的顺序、停止规则、SITL 预算和暂停 1 边界继续适用。原 `dual_intent_v05.json`、原 DR、原诊断和停止报告作为只读历史证据保留。新的正式候选来自 `dual_intent_v05b.json`，其结果写入独立目录。

## 固定变更

- 新增 `random_spawn_v2`，声明 `intent_agnostic=true`，保留 `random_spawn_v1`。基础场景编号 `base_index` 对应的机数按列表 `[2, 3, 4]` 以 `base_index % 3` 为下标轮流取值；同一基础场景的候选抽取不得改变机数。
- 区域宽高分别为 \(N u_x\)、\(N u_y\)，两个单位尺度独立均匀采自 \([11,16]\,\mathrm{m}\)；区域中心在 ENU 原点的东西、南北各 \(\pm10\,\mathrm{m}\) 内，完整区域必须在世界边界内。
- 编队只取 `line`，机间距 \([8,12]\,\mathrm{m}\)、旋转角 \([-20^\circ,20^\circ]\)；进场方向、进场距离 \([10,20]\,\mathrm{m}\)、横向偏移、航向及编号随机化沿用 v1。
- 新 profile 除采样器及 `max_candidates_per_base=20` 外沿用 v05。记录文件 SHA256 和规范化指纹，不修改旧 profile。

## DR 预注册门禁

DR 只做纯规划，不启动 SITL。验收须同时满足：

1. 联合可行候选数除以**全部候选抽取数**至少为 30%；
2. 130/130 个基础场景接受，按机数的接受数严格为 2 机 44、3 机 43、4 机 43；
3. 接受集侦察 observe 阶段对每条带以实际扫描线中心距 \(\delta=W/\lceil W/(4\,\mathrm{m})\rceil\) 计算 \(d=W-\delta\)，没有 \(d<7\,\mathrm{m}\)；并与完整时间感知间距检查的 observe 最小距离交叉核对；
4. 生成附件哈希完整，报告拒绝原因，以及候选抽取与接受集的机数、进场方向、解析剖分轴、旋转角、区域宽高、速度分布。

任一项不通过，停止并报告；不得继续改采样范围、种子或候选上限。

## 验证选例与后续顺序

所有验证场景仅从新 DR 的接受集中选择。优先条件依次为：VR1 侦察、3 机、东/西进场；VR2 侦察、4 机；VP1 巡逻、3 机、`K=2`、返航；VP2 巡逻、4 机；VP3 巡逻、2 机、`K=3`、不返航。VP4 复用 VP1 的物理场景和任务采样结果，仅将 `terminal_hold_s` 改为 1。缺少可用场景时，对该例确实指定的条件按“进场方向 → K → 是否返航”的顺序逐项放宽，逐步记录；机数与意图不放宽。VP2 在合格的 4 机候选中优先选择接近巡逻预筛选下限的场景。若新 DR 门禁与选例均通过，就按 r1 完成 VP1–VP4、VR1–VR2、HD、试生产；然后在暂停 1 提交合并报告，并加入新旧 profile 的构成对比。

v0.5 数据契约补充 line-only 的机理及限制、区域尺寸和机数分层规则；新增公开场景加载接口，只允许返回目标区域的四个 ENU 角点。
