# WP-S 参数比较 v2

日期：2026-10-02。依据：用户确认与 [实施计划补充](v04_stage01_plan_addendum.md)。本次调整只涉及 v3 逐运行参数读回的分类与校验；已接受的 WP-S GO、固件及参数模板保持原样。

## 固定配置与运行状态

| 对象 | 检查规则 | 证据 |
| --- | --- | --- |
| STAT_RESET | 不与前次值相等比较；以 2016-01-01 UTC 为零点换算，距本次运行启动时刻不超过 300 s，边界包含 | 原始值、换算 UTC、启动时间、时差、容忍量及判定 |
| STAT_BOOTCNT | 必须为 1 | 实际值、固定期望值及判定 |
| STAT_FLTTIME、STAT_RUNTIME | 必须为 0 | 实际值、固定期望值及判定 |
| SYSID 和已声明的 home 派生字段 | 沿用原实例差异规则 | 具体差异及解释，SYSID 必须匹配连接实例 |
| 导航、控制、WPNAV_* 及其他参数 | 继续与已接受 WP-S 基线严格核对；未解释变化拒绝 | 完整差异清单，不按前缀笼统忽略 |
| 参数集合及读回完整性 | 表项齐全、完整标志与计数一致；部分读回拒绝 | 每机计数、缺项、状态和请求日志 |
| 固件、模板 | SHA256 及固件版本继续与 GO 证据链一致 | 原 GO 哈希链及本次指纹 |

在当前“全新独立实例、启动即读回”的预检流程中，`STAT_BOOTCNT=1`、`STAT_FLTTIME=0`、`STAT_RUNTIME=0` 是全新启动的固定契约；任一变化按 EEPROM 复用或非全新启动处理并拒绝。这些统计计数没有被加入可变值白名单。时间线与原值继续保留，避免将运行状态差异隐藏为配置一致。

`STAT_RESET` 先检查有限数值与时间可解释性，再使用带时区的本次运行启动时间比较；不能用比较时刻、run ID 估计或前次运行时间替代。日期换算不受执行机器本地时区影响。±300 s 仅用于这项统计时间合理性检查，不放宽飞行时序、观测时钟或 AC-4 的容忍量。

## 版本和历史保留

比较策略版本为 `wp_s_parameter_comparison_v2`，写入本次 metadata 和每机参数附件的比较证据。统计时间合理性、固定计数和完整配置比较是不同检查，最终须全部通过。读回失败或统一取消的飞机仍保存版本与部分证据，不能标成比较通过。

旧 V01 `20261001T182936Z_6bca981d` 继续是失败运行。离线对其中真实包检查 STAT_RESET 只能说明该字段符合新规则；uav_01 的部分表仍不符合完整性，不能由原始日志补齐后回写或改判。旧 WP-S 和 V01 的原文件均受哈希保护。

若固件或模板实际变化，仍必须重新 WP-S。此次文件指纹未变化，用户已明确确认无需重做 WP-S；统计时间的分类修正不生成新的飞行控制配置。
