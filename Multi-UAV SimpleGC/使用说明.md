## 历史 v0.2.2 使用示例（非当前开发步骤）

以下保留 v0.2.2 的原接口示例与规则口径，不是新引擎命令或当前运行授权。该阶段的质量策略和验证记录见 [v0.2.2 补丁说明](v0.2.2补丁说明.md)；0.2.0 与 0.1 的记录分别在 `第二轮迭代方案与验证说明.md`、`改进方案与验证说明.md`。旧残差阈值不能替代 v0.6.1 的时间政策；旧分析操作也不能用于覆盖冻结数据。

在本工程目录的 PowerShell 7 中运行：

```powershell
conda run -n llm --no-capture-output python main.py validate scenarios/demo_2uav.json
conda run -n llm --no-capture-output python main.py run scenarios/demo_2uav.json
```

程序自动启动自己的本机 SITL 进程，不需要手动运行旧启动器。运行输出位于 `runs/` 下的独立目录。

三类任务示例可以直接执行，结束后自动完成离线分析：

```powershell
conda run -n llm --no-capture-output python main.py run scenarios/task_point_visit_3uav.json
conda run -n llm --no-capture-output python main.py run scenarios/task_patrol_3uav.json
conda run -n llm --no-capture-output python main.py run scenarios/task_coverage_3uav.json
```

任务输入位于 `tasks/`。修改任务后使用 `plan <任务文件> --output <新场景文件>` 编译，再运行新场景。`analyze <运行目录>` 可重新分析历史数据，`dataset <多个运行目录> --output <新目录>` 可导出按任务族划分的数据集。运行根目录的 `analysis_latest.json` 指向最新分析结果。

`run/batch/analyze` 可以追加 `--quality-policy quality_policies/default_v022.json` 指定质量策略。默认数据集合格标记为 `benchmark_eligible`，严格子集为 `strict_benchmark_eligible`。缺少策略信息的旧分析必须先重新分析；不同策略结果需要分开导出。重分析只新增分析文件和更新最新指针，原始日志与执行元数据保留。

`scenarios/` 提供 1、2、6 架飞机的短距离示例。请先完成短场景验证，再构建自己的阶段与目标点。

原单机程序保留为 `flyControl.py`；直接运行它仍采用旧方式连接第一个端口、串行执行旧轨迹任务。这一兼容入口与新多机入口的功能边界不同。
