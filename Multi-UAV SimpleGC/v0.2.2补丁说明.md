# v0.2.2 质量策略、过滤一致性与验证说明

更新日期：2026-09-29。修改对象：`Multi-UAV SimpleGC`；原始 `SimpleGC` 副本保持原状。

本次落实进入 v0.3 前的最后一轮质量治理：时钟分级、统一观测过滤、异常统计、分析可追溯性、依赖整理及自动测试。已有多机执行、三类任务、SIM 真值和按任务族划分数据集的能力保留。本轮未增加共享区域任务分配、传感器模拟或主动时钟同步。

## 1. 修改后的处理流程

```text
场景与质量策略
  → 本机 SITL 执行 / 原始 MAVLink JSONL 与 BIN 留存
  → 共享观测校验
      ├─ 在线 samples.csv：当前消息、内容有效性、消息年龄
      ├─ processed.csv：主机接收时间重采样
      └─ observations.csv：被动源时钟映射，失败时明确标记接收时间回退
  → 保留异常样本为插值屏障，缺失证据不拼接
  → 任务语义、观测/真值覆盖率、间距与时钟分级
  → 版本化分析 + 策略内容/SHA256 + 原始证据/产物摘要
  → 同策略数据集，保留失败样本与任务族划分
```

三个观测出口共享内容判定，但时间轴和采样方式不同，不承诺逐行一致。在线采样额外判断消息年龄；离线分析额外判断时间序列和插值区间。

| 模块 | 本次变化 |
|---|---|

| `swarm_sim/runner.py`、`swarm.py` | 将指定策略贯穿运行、导出和分析；增加 CLI 参数 |

## 2. 时钟分级与样本资格

采用现有 SYSTEM_TIME 被动映射的留出样本接收残差 P95，默认分级如下：

| 档位 | 条件 | 可进入默认合格集 | 可进入严格子集 |
|---|---|---|---|
| `strict` | 时钟模型可用，P95 不超过 20 ms | 是，且其他检查通过 | 是，且其他检查通过 |
| `acceptable` | 模型可用，P95 大于 20 ms、且不超过 50 ms | 是，且其他检查通过 | 否 |
| `failed` | 模型可用，P95 大于 50 ms | 否 | 否 |
| `unknown` | 模型不可用、证据不足或残差非法 | 否 | 否 |

所有飞机均须符合要求。汇总时，有 `failed` 即为 `failed`；否则有 `unknown` 即为 `unknown`；其余按最差有效档位汇总。每架飞机的分级也保留。

- `benchmark_eligible`：时钟为 strict 或 acceptable，并且执行完整结束、观测和真值有效率通过、观测与真值间距均可确认无风险、任务语义验证成功。
- `strict_benchmark_eligible`：满足默认合格条件，且所有飞机时钟均为 strict。
- `timing_diagnostic_pass`：只表示时钟处于前两档，不能代替完整资格判定。
- 无 TaskSpec 的旧航点模式继续采用基础运行门槛，不会自动取得任务数据集资格。

接收残差包含传输和操作系统调度抖动，不是绝对同步精度上界，也不等于模型感知精度。恢复默认 50 ms 可接受档不会提高时钟本身的精度；它让样本的质量等级和适用范围更明确。

## 3. 统一过滤与异常点屏障

校验范围包括必需字段、数值类型、NaN/Inf、源时间、经纬度与局部 ENU 范围、水平速度和垂直速度。速度转换继续遵循 MAVLink 轴向：东向来自 vy，北向来自 vx，向上来自负 vz。

默认内容保护阈值：水平速度不超过 50 m/s，垂直速度绝对值不超过 30 m/s，东/北坐标各不超过正负 2500 m，高度范围为 -100 至 200 m。这些是异常数据保护阈值；场景仍有自己的运行速度、区域和航路约束，不能据此宣称飞机具有相应飞行性能。

异常消息的原始内容仍保存在 raw JSONL；用于计算的样本标记无效。离线流程保留可定位的异常时间点，防止删除异常后在两端正常样本之间插值。即使异常位于两个输出网格点之间，也会保守地屏蔽跨越该异常的区间终点，确保驻留、覆盖和间距验证不能重新连接这段缺失证据。超出 `max_gap_s` 的长间隔同样处理。

不能定位的消息时间戳、重复/回退的源时间或倒退的接收时间会记录 `observation_timeline_errors`，该机离线观测轨迹全部置无效。本轮采用保守拒绝，不自动修复时钟重置或跨段拼接。

## 4. 异常统计如何读取

最新分析 `quality.json` 的 `observation_filter.<agent>` 同时包含 `whole_run` 和 `evaluation_window`。每一范围具有 `total_messages`、`accepted`、`rejected`、`dropped`。

统计单位是原始 GLOBAL_POSITION_INT 消息，每条消息在每一适用范围内计一次，不重复累计在线重采样点。评估窗口使用包含两端的主机接收时间范围，并保存实际边界；它不完全等同于映射后输出时间轴。

拒绝原因按以下顺序选取一个主原因：

1. `missing_fields`：必需字段缺失。
2. `invalid_type`：字段不是数值或为布尔值。
3. `non_finite`：NaN/Inf。
4. `invalid_timestamp`：源时间或接收时间非法。
5. `position_out_of_bounds`：经纬度/ENU 位置越界。
6. `horizontal_speed_out_of_bounds`：水平速度越界。
7. `vertical_speed_out_of_bounds`：垂直速度越界。

总消息数等于 accepted 加 rejected，rejected 等于各主原因计数之和。多项异常只记首个主原因；统计不是每一种潜在错误的独立发生次数。时间序列回退等整段错误单列，因此内容 accepted 数量不能直接当作最终有效样本数。

`samples.csv` 新增 `position_invalid_reason`。旧版含义混杂的 `dropped_invalid_positions`、`dropped_unreasonable_velocity` 不再作为新分析的统计接口；下游读取脚本应迁移到上述结构。`observations.csv` 和 `processed.csv` 的已有特征及有效掩码列保持兼容。

## 5. 策略与历史数据可追溯性

默认策略文件为 `quality_policies/default_v022.json`，包含版本、时钟阈值、内容保护阈值、有效率阈值和过滤/插值模式。CLI 允许提供部分字段覆盖默认值；保存的是补全并校验后的完整策略。未知字段、非有限数值和不合法的阈值关系直接报错。

每份分析与数据集保存 `quality_policy` 和 `quality_policy_sha256`。策略 SHA256 按规范化 JSON 计算，修改阈值即改变摘要。场景中的 `record_hz`、`max_gap_s`、`min_separation_m` 另存于 `evaluation_context`；即使策略相同，比较实验时仍须检查这些场景差异。

版本区分如下：

- 原始 `metadata.json.version`：采集该次数据时的仿真代码版本。历史 0.2.0 保持原值。
- `manifest.json.simulator_version`：复制该原始版本，便于检索。
- `manifest.json.analysis_version`：本次重新分析代码版本，当前 0.2.2。
- `analysis_schema_version`：当前分析结构版本 2。
- `quality_policy.version` 及摘要：分析采用的策略标识及完整内容指纹。

每次 `analyze` 新建 `analysis_v022_<时间>_<随机后缀>`，只更新 `analysis_latest.json` 指针；不覆盖原始 metadata、raw、BIN、旧分析和旧根目录质量报告。文件摘要继续用于检查分析产物和来源是否变化。

导出数据集时，缺少策略信息的旧分析会报错，要求显式重新分析。不同策略摘要会报错，要求统一策略重分析或分别导出。检查在创建输出目录前执行，不会为了凑齐数据而隐式重分析或把失败样本删除。

## 6. 使用方式

在项目目录的 PowerShell 7 中使用 `.conda-env` 指定的 `llm` 环境：

```powershell
# 逻辑测试，不启动 SITL
conda run -n llm --no-capture-output python -m unittest discover -s tests -v

# 新任务运行：策略同时用于在线采样和两个离线出口
conda run -n llm --no-capture-output python main.py run scenarios/task_point_visit_3uav.json --quality-policy quality_policies/default_v022.json

# 历史日志重新分析，不启动 SITL
conda run -n llm --no-capture-output python main.py analyze runs/point_visit_three_20260925T100252Z_328cb383 --quality-policy quality_policies/default_v022.json

# 同策略结果导出；输出目录必须不存在
conda run -n llm --no-capture-output python main.py dataset runs/point_visit_three_20260925T100252Z_328cb383 --output datasets/my_v022_dataset

# 本轮七条历史样本的可重复验证脚本；每次选择新的输出目录
conda run -n llm --no-capture-output python scripts/verify_v022.py --output datasets/my_v022_verification
```

不传 `--quality-policy` 时使用当前代码默认策略，不自动沿用历史 metadata 中的策略。需要复现实验时，请保存并指定当时的策略文件，同时记录分析版本。`batch` 支持相同参数。

## 7. 依赖与自动测试

`requirements.txt` 保留运行依赖 `pymavlink==2.4.50`。`requirements-dev.txt` 引入运行依赖并额外声明可选 `pytest>=7.4.0,<9`。本轮未安装任何包；当前 `llm` 未安装 pytest，但项目测试基于标准库 unittest，可直接执行。

当前已验证的项目路径不直接依赖 NumPy。禁用 NumPy 导入时，全部 63 项逻辑测试仍通过；同条件下读取一份真实 BIN 得到 684 条 SIM 记录与 1202 项参数。这仅覆盖当前使用路径，不代表 pymavlink 的所有可选功能都不需要 NumPy。

仓库根目录 GitHub Actions 配置在 push、pull_request 和手动触发时，以 Windows / Python 3.12 安装运行依赖并执行 unittest。该工作流不启动真实飞行，本轮未提交/推送，也未确认 GitHub 远端执行结果。

## 8. 本轮验证结果

本地 `llm` 环境：63 项测试全部通过，其中新增 13 项覆盖时钟边界与未知状态、策略合法性与摘要、速度轴向、异常原因计数、三个观测出口一致性、子网格异常阻断驻留/覆盖、长缺口、历史版本保留和混合策略拒绝。

对已有 6 条三机任务记录及 1 条超时记录进行离线重新分析。这部分只读取历史日志；另补跑了下述新代码三机集成验证。历史样本结果如下：

| 历史记录 | 时钟汇总 | 任务语义 | 默认合格 | 严格合格 |
|---|---|---|---|---|
| 两次点访问 | acceptable | 成功 | 2 条 | 0 条 |
| 一次修正后的巡逻 | acceptable | 成功 | 1 条 | 0 条 |
| 一次早期巡逻 | acceptable | 失败 | 0 条 | 0 条 |
| 两次覆盖扫描 | acceptable | 成功 | 2 条 | 0 条 |
| 一次超时 | unknown | 无法确认 | 0 条 | 0 条 |
| 合计 | 7 条 | 5 成功、1 失败、1 未知 | 5 条 | 0 条 |

数据集 `failed_runs=1` 专指执行状态未完成的超时记录；另一个巡逻样本虽然完成执行，但任务语义失败，因此也不合格。没有把这两类失败混为一个计数。

6 条正常任务运行均为每机全程各 1 条位置越界消息、评估窗口内 0 条内容拒绝，说明全程启动阶段与任务窗口应分别统计。超时样本为 1 条位置越界拒绝，仍保留为不合格记录。所有历史原始证据及校验的旧分析文件 SHA256 保持不变。

## 9. 下一步计划与冻结边界

v0.2.2 可作为后续任务研究的执行与数据质量基线。本轮已完成一次新代码三机点访问的真实 SITL 冒烟验证；巡逻与覆盖使用历史真实日志重分析，未在本轮重新飞行。更大规模、更多随机种子及长时间运行仍需单独实验，不能从一次冒烟验证外推。

v0.3 首个可交付功能建议集中在“共享区域侦察”：整个集群接收一个区域任务，按无人机能力与约束分配子区域，编译到已有执行阶段，再用所有飞机轨迹的覆盖并集验证整体任务。先提供可重复的规则分区基线、统一坐标与边界约束、任务族标签和失败判定，再扩展不同分配算法。

暂不进行大规模目录搬迁，不将主动 TIMESYNC、真值速度补全或复杂传感器建模作为这一任务闭环的前置条件。现有观测仍是已知身份的合作式遥测；几何覆盖仍不能解释为真实侦察探测率，独立 SITL 也不提供共享碰撞动力学或在线避碰。
